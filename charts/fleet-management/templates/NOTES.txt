Upgrading: Helm installs the files in crds/ only on the first install and never upgrades them. After upgrading the
chart, apply the CRDs yourself (--force-conflicts is needed because Helm owns .spec.versions of the CRDs it created):

  helm show crds <chart> --version {{ .Chart.Version }} | kubectl apply --server-side --force-conflicts -f -

or, from a checkout of this chart version:

  kubectl apply --server-side --force-conflicts -f charts/fleet-management/crds/

Kubernetes 1.30 or newer is required (CRD validation ratcheting).

Connect-RPC API (alloy-remote-config endpoint)
-----------------------------------------------
The Alloy remote-config API is reachable inside the cluster at:

  {{ include "fleet-management.resourceName" (dict "suffix" "api" "context" $) }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}

To test locally, forward the service port:

  kubectl port-forward svc/{{ include "fleet-management.resourceName" (dict "suffix" "api" "context" $) }} \
    {{ .Values.service.port }}:{{ .Values.service.port }} -n {{ .Release.Namespace }}

Point Alloy at it with a remotecfg block (identity attributes: tenant, collector_group, and any key your matchers use):

  remotecfg {
    url            = "http://{{ include "fleet-management.resourceName" (dict "suffix" "api" "context" $) }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}"
    id             = constants.hostname
    poll_frequency = "1m"
    attributes     = { "tenant" = "acme", "collector_group" = "{{ .Values.defaults.collectorGroup.name }}" }
  }

The default CollectorGroup only contains collectors that set collector_group to its name ("{{ .Values.defaults.collectorGroup.name }}"). Collectors in
no group and with no tenant binding get the PipelineConfig labeled fleet.pkarakal.com/default-pipeline-config.
